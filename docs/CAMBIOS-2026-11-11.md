## 7. Seguridad de Firestore

### Situación encontrada (15/10/2026)

Las reglas desplegadas eran las de modo prueba:

`
match /{document=**} {
  allow read, write: if true;
}
`

Cualquiera con la API key pública de la app podía leer y escribir toda la base
de datos. Además, el modo prueba caduca a los 30 días: sobre el **14/11/2026**
la app habría dejado de guardar sin explicación.

### Reglas aplicadas

Archivo `firestore.rules` (con `firebase.json` para el despliegue):

- `familias/{familyId}/**`: solo si `familyId` es el UID del usuario o su
  email con los puntos cambiados por `_` (así se construye el id en
  `UsuarioProvider`).
- `usuarios/{uid}/**`: solo lectura/escritura del propio UID; se mantiene
  únicamente para la migración inicial de datos antiguos.
- Todo lo demás queda denegado.

Desplegadas con:

`ash
firebase deploy --only firestore:rules --project app-home-familia
`

Compilación correcta y **verificado en la app**: tras reiniciar, los datos del
usuario siguen cargando y guardando.

> Nota: la API de simulación de reglas (`projects:test`) no respondió desde
> esta red, por lo que la validación se hizo en vivo. Si en el futuro se tocan
> las reglas, conviene probarlas con el emulador antes de desplegar.
